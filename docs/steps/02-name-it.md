# Name It

**Give your project a name. It forces you to decide what it's really for.**

A name is more than a label. Choosing one means saying, in a few words,
what the app is *for*. That's why Name It starts with a single sentence,
the purpose, and only then looks for a name that fits it.

## What happens

1. **The purpose line.** One plain sentence about what the app does for
   whom. Not a slogan: "Markdown slides delivered live to your audience's
   phones", not "Revolutionizing presentations".
2. **Names.** Claude suggests a handful (descriptive, short, playful),
   each with a reason, and welcomes yours. Each one is held up against
   the purpose line.
3. **The web version of the name.** Lowercase, no spaces: `SlideIt`
   becomes `slideit`. This becomes your web address and your project's
   name everywhere else.
4. **Is it free?** Claude checks the name is free on GitHub, on Vercel,
   and as a `.vercel.app` web address, so the next step has no surprises.

## What you end up with

| | Example |
|---|---|
| A display name | SlideIt |
| A web-safe name | `slideit` |
| A one-line purpose | Markdown slides delivered live to your audience's phones. |

Saved in `PRODUCT.md`, ready for Claim It. Still nothing online.
